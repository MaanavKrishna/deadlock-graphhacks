# Deadlock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build the complete graph-native capacity exchange MVP, including reproducible local operation and submission documentation.

**Architecture:** A TypeScript domain engine evaluates participant constraints. A FalkorDB repository discovers cycles and atomically persists agencies, agreements, reservations, and events. Express exposes a validated local API; React presents a network-led exchange desk.

**Tech Stack:** Node >=22.12, TypeScript, React, Vite, Express, Zod, official falkordb/falkordblite, Vitest, browser QA.

**Spec:** docs/superpowers/specs/2026-10-18-deadlock-design.md

## Global constraints

- All durable state lives in FalkorDB; no fallback matching store.
- Cycles contain three or four distinct active agencies and come from a Cypher traversal.
- Maximum 6 negotiation rounds; code owns feasibility.
- Each human approval is explicit; final commitment is atomic and idempotent.
- Synthetic data only. No external messages, payments, or service fulfillment.
- Single Node server serializes mutations; distributed workers unsupported.

## Review focus

- Two proposals compete for the same capacity: only available hours may be held.
- Profile/availability changes during approval: invalidate stale proposal and release all holds.
- Repeated approval or cancellation: no duplicate commitment or negative counters.
- Invalid request/model output: reject safely without corrupting graph state.
- Reload/restart: accepted terms, approval flags, events, and counters stay consistent.
